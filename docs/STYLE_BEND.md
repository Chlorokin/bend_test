# Bend style guide

Written from building Proof Tickets (`core/`): 10 laws, about 950 lines of
proof for about 710 lines of code, checked in about 1.3 s. Bend 2.0.25, pinned
in `scripts/setup.sh`.

Bend owns **decisions**: authorization, state machines, balances, merge
functions, and anything with a law. It does not own IO, bulk text output or
plumbing (see `STYLE_C.md`).

## 1. Files and roles

| File | Owner | Contents |
|---|---|---|
| `LAWS.bend` | the human | Claims only. Each law has a plain-English comment above it; the server shows those comments on the page. The AI never weakens, removes or renames a law without asking. |
| `PROOF.bend` | the AI | A `def Laws.<name>` for every law, plus lemmas. |
| `kit.bend` | shared | `LE`, `le_case`, `T`: the vocabulary code and proofs share. |
| `*.bend` | the AI | The code. |

`bend PROOF.bend` must print `All terms check.` before every commit. The
server re-runs it at boot and refuses to call itself proven otherwise.

## 2. Design for proof (the biggest lever)

How the code is shaped decided the proof effort more than anything else.

- **Store logs, derive state.** Keep a list of events with their status and
  compute balances by summing. Then "posting" moves an amount from one sum to
  another, and every lemma is "this sum grew" or "this sum shrank". Avoid
  `Nat.sub`: it stops at zero and breaks equations.
- **Type identities.** `Seat{k}`, `Wallet{u}`, not raw numbers. Then "a hold
  never credits a seat" is a fact the checker computes
  (`Id.eq(Tickets{u}, Seat{k})` reduces to `False`), not arithmetic about ID
  ranges.
- **Comparisons return evidence.** `le_case(a, b) -> Or(LE(a,b), LE(1+b, a))`
  instead of a `Bool`. The branch the program took then hands the proof the
  fact it needs.
- **One helper per check, taking the verdict as a parameter**
  (`create.a(.., same)`, `create.b(.., found)`, ...). A proof then mirrors the
  program helper for helper.
- **Make illegal states unrepresentable** before reaching for a law. A seat
  state that holds one owner needs no "one owner" law.
- **Laws about all values, not specific ones.** Prefer "for every amount". The
  checker computes numbers one step at a time: `30000 + 30000` overflows its
  stack, `10000 + 10000` doesn't.

## 3. Laws worth writing

- **Invariant preserved by a step**, then induction over a list of commands
  (`replay`): "for any sequence of commands, of any length, with any ids".
- **All or nothing:** either every effect happened or the state is unchanged.
- **Idempotence:** `f(f(x)) == f(x)` (retries, merges).
- **Round trip:** `parse(render(x)) == x` (SSE framing, URLs, serialization).
- **Non-interference:** the output for user A is identical for any two states
  that differ only in user B's private data. This is the strongest
  confidentiality law, and a good fit for Bend.
- **Structure independence:** `tags(render(x, name1)) == tags(render(x, name2))`
  (user text cannot change markup).
- **Merge laws** for local-first data: commutative, associative, idempotent,
  nothing lost.

Name laws as sentences a reviewer can check: `seat_never_oversold`, not
`inv3`.

## 4. How proofs work, practically

- A law is a type; a proof is a `def` of that type. `{a == b : T}` is equality;
  `{==}` proves it when both sides compute to the same thing.
- `match` gives case analysis; a recursive call is the induction hypothesis.
- **Rewrite direction.** `%e : P` with `e : {a == b}`: the current goal must be
  `P` with `_` replaced by **b**, and the new goal is `P` with `a` there. If the
  goal contains `a`, rewrite with `sym(.., e)`. Getting this backwards was the
  single most common error.
- **Case-split on a computed Bool while keeping the fact:**
  `bool_case(b, P, t, f)`, where `t` receives `{True == b}`. See `PROOF.bend`.
- **Contradictions:** `false_true(e : {False == True}) : Empty` via
  `%e : K.T(Bool.not(_)); Unit{}`, then `Empty.absurd`.
- **Mirror lemmas:** for `f.a .. f.g`, write `safe_a .. safe_g`, each matching
  the same parameter. It's tedious but mechanical.
- **Shape lemmas pay off.** Prove once that "a transfer either leaves the
  ledger unchanged or commits exactly one entry", then reuse it for several
  laws instead of walking the helpers again.
- **Generate big case splits with a script.** The 36-case `id_eq_sound` and the
  12-way `genesis_bound` were generated by Python, not typed.
- Use `?name` to print a goal while writing a proof. `?TODO` is a hole, and it
  fails the check.

## 5. The rules that bite (all hit during Proof Tickets)

| Error | Fix |
|---|---|
| `consumed more than once` | mark the binder `+x` (it must be `Data`), or `+field` in a pattern, or pass the value to a helper |
| `a match on a parameter or field` after a `let` | lets go *inside* the case branches, not before the `match` |
| matching an earlier parameter after a later one | use accessor defs (`log(L)`, `ids(L)`) instead of destructuring |
| `a parameter or field scrutinee` (matching a local) | give the value its own def, or use `Pair.fst` / `Pair.snd` |
| `expected a decreasing self-call` | put the shrinking argument first |
| `expected a defined name` | define before use (order matters) |
| `expected Data, observed Type` | `A & B` is a `Type`; return `Type`, or erase the parameter with `-` |
| `expected -x` | an erased (`-`) value can't be passed where a live one is matched; make it live |
| `cannot infer` | annotate: `{L.Seat{k} : L.Id}` |
| proof values used twice | proofs are affine too; mark law hypotheses `for +s:` when both branches need them |
| no `if` | `match b: case True{}: .. case False{}: ..`, or `Bool.pick` |

## 6. Performance

- **Native only for anything fast.** `bend x.bend -o x`: about 3× C on one
  thread, and it scales with `--threads`. The JavaScript target (and `import`
  of `.bend` from JS) is about 50× slower and single-core; fine for
  development, the browser, and light work.
- **`String` is a linked list of characters.** Building a 195 KB HTML table
  took 11 ms natively versus 0.25 ms in C. Keep Bend strings for short text
  and proofs. Bulk output goes through C serializers, or an `Array<U32>` byte
  buffer if it must stay proven.
- **Runtime `Nat` stops at 2⁴⁸−1.** Use small sequential ids and cents.
- **Parallelism:** `a b = f(x) g(y)` must be balanced; the scheduler never
  moves tasks.
- **IO:** one event loop. Blocking C effects use `io_work`.

## 7. Interop

- From JS: `import M from "./m.bend"` with `.tools/bend/bend2/main.ts`
  preloaded (`bunfig.toml`). Constructors are `{$: "Name", field}`, `Nat` is
  `BigInt`, `Bool`/`String`/`U32` are native, and dotted names are
  `M["Id.eq"]`.
- From C: effects only (Bend calls C). There is no documented way for C to
  call Bend in-process.
- **Cross-check the model against reality** at runtime whenever Bend models an
  external system (TigerBeetle, SQLite). Proofs cover the model; the
  cross-check covers the gap.

## 8. Checklist

- [ ] Could a type make this law unnecessary?
- [ ] Is the state a log with derived views, with no subtraction?
- [ ] Do comparisons return evidence?
- [ ] Is every law "for all", with no big concrete numbers?
- [ ] Is `bend PROOF.bend` green?
- [ ] Is anything hot using `String`? Move it to C or to arrays.
